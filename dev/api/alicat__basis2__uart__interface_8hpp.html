Detailed Description

CRTP serial transport for the Alicat BASIS-2 driver.

The driver itself only deals in byte buffers. Each platform (ESP-IDF, mock test harness, embedded MCU project, …) provides a concrete adapter inheriting from this CRTP base, implementing three small methods:

bool write(const uint8_t* data, std::size_t length); // true = all sent std::size_t read(uint8_t* out, std::size_t max, uint32_t timeout_ms); void flush_rx();

and, optionally, two hooks the base class finds at compile time:

void delay_ms_impl(uint32_t ms); // sleep >= ms void log_impl(const char* tag, const char* fmt, ...); // printf-style

Without delay_ms_impl, delay_ms() does nothing: portable code has no time base to busy-wait on. The driver calls delay_ms() before every request to leave the Modbus-RTU 3.5-character idle gap (Modbus over Serial Line V1.02, section 2.5.1.1), so a port without the hook must leave the gap itself (in write() or in the UART). Without log_impl, log() does nothing; the driver logs every failed transaction through it.

Concrete adapters should map RS-485 DE/RE handling (when needed) onto the underlying UART driver's RS-485 mode before passing the adapter to the BASIS-2 driver.
